# 测试报告

所有数据来自同一台机器（2× RTX 3090，PCIe x8/x8 + P2P），同一套权重，**只换引擎参数**。
测量日期 2026-11。

---

## 1. 口径定义（重要）

不同口径能差 40%，横比前先对齐：

| 口径 | 定义 | 用途 |
|---|---|---|
| **1c** | 5 条中文短任务，各生成 256 tok，`temperature=0`，取中位；**只算首 token 到末 token**（不含 prefill） | 单流交互速度 |
| **4c / 8c** | 并发 4/8 路，60 字符随机 prompt + "写代码"，各 128 tok，**聚合 = 总生成 tok / 墙钟** | 多用户吞吐 |
| **PF-xK** | 随机串 prompt（实测 xK token），`max_tokens=8`，3 次取中位，**= prompt_tokens / TTFT** | prefill 速度 |
| **双点法** | 同一 prompt 用 `max_tokens=16` 与 `=272` 两次，相减抵消固定开销 | 抗投机突发的单流值 |

> 1c 只算解码段，所以天然比"端到端"高；投机解码会让每条请求出现突发，端到端口径的方差更大。

| 项 | 值 |

| GPU | 2× RTX 3090 24G（sm86），Gen4 x8/x8，**P2P 13.19 GB/s** |
| 显存占用 | 21.1 GB / 卡（权重 18G + KV + 草稿 1.2G） |

## 3. 主结果

| 项目 | 数值 |
|---|---:|
| 1c | **272.0 tok/s** |
| 4c | **481.9 tok/s** |
| 8c | **774.0 tok/s** |
| PF-8K | **3341 tok/s** |
| PF-32K | **2890 tok/s** |

> 被双点法扣掉了。两个数都真实，看你要不要算 prefill 和调度。

## 6. Roofline：为什么说已经贴线

| 环节 | 实测 | 理论上限 | 占规格 |
|---|---|---|---:|
| prefill 8K | 3341 tok/s → 2.45s | 8K × 27e9 × 2 = 442 TFLOP / INT8 250 TOPS = 1.77s | **72%** |
| decode 单流 | 17.4 ms/步（每步 3.09 token） | 每卡读 ~13.2 GB / 880 GB/s = 15.0 ms | **86%** |
| decode 8 并发 | 653.7 tok/s（长输出实测） | 每步验证 8 路 × 8 位置 = 64 token → 算力绑定 | 已贴线 |

**8 并发为什么不是线性？** 投机解码每步要验证 `并发数 × (1+SN)` 个位置 —— 8 路时每步要过 64 个 token，
目标模型从"带宽绑定"变成"**INT8 算力绑定**"。这解释了"带草稿 8c 只有 1c 的 2.85 倍，而不带草稿能到 8.2 倍"。
想突破只有两条：换硬件（更高算力/带宽），或降到 INT4×INT4（实测 MMA 501 TOPS = 2×，但 W4A4 精度掉到 0.93 以下）。

## 7. 精度细节

**GSM8K-500**：476/500 = 0.952。失败 24 题集中在多步算术与单位换算，与量化无关（bf16 基线同区间）。
> 注意：30 题小样本曾报 0.967，**样本太小不可信**，以 500 题的 0.952 为准。

**HumanEval-164**：

| 思考档 | pass@1 |
|---|---:|
| 关闭（`enable_thinking=false`） | 0.927（152/164） |
| `reasoning_effort=low` | **0.951（156/164）** |

思考对代码是净正收益；而 `low` 的思考 token 只有 `xhigh` 的 36%（GSM8K-100 上两者同分 95/100），
**编码/agent 场景建议默认 `low`**。注意 `medium` 档在模板里**不加任何指令**，反而比 `xhigh` 更啰嗦。
